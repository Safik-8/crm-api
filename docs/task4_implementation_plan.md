## Technical & Architecture Standards (from `prompt.md`)

### 1. Backend 4-Layer Standard (`crm-api/src/modules/revenueReport/`)
- **Validation Layer (`revenueReport.validation.js`)**: Zod schema validation for query params (`page`, `limit`, `startDate`, `endDate`, `rankingPeriod`, `companyId`, `branchId`, `teamId`, `courseId`).
- **Routing Layer (`revenueReport.routes.js`)**: Endpoints registered in `crm-api/src/index.js` (line 120+) protected by `authenticate`. GET routes use `hasPermission("REPORT", "canView")` and POST write routes use `hasPermission("REPORT", "canCreate")`.
- **Controller Layer (`revenueReport.controllers.js`)**: Clean Express handlers delegating to services and returning standardized responses via `sendSuccess`. No direct database calls or unhandled try/catches; uses `next(err)`.
- **Service Layer (`revenueReport.services.js`)**: Financial domain brain enforcing multitenancy (`applyRoleScopingGuard`), division-by-zero safe growth formulas, pagination wrappers, server-side `ExportLog` creation, and `AuditLog` entries using the repository audit logger pattern established in `user.repository.js` / `team.repository.js`.
- **Repository Layer (`revenueReport.repository.js`)**: Direct Prisma Client queries aggregating `RevenueLog` (joined with `Deal`, `Course`, `Customer`, `Team`, `Branch`, `Company`) to prevent database schema mismatch.

### 2. Frontend Feature Module Standard (`crm-web/src/features/revenueReport/`)
- **Feature Folder Structure**:
  - `services/`: `revenueReportService.js` (Consumes `axiosClient`).
  - `hooks/`: `useRevenueReport.js` (TanStack Query hooks with pagination & cache invalidations).
  - `components/`: Presentational components using Tailwind CSS layout (Zero forbidden MUI containers like `Box` or `Typography`). Includes `BranchRevenueTable.jsx`.
  - `pages/`: `RevenueReportPage.jsx` orchestrator.
- **Design System**: Sharp outer card containers (`rounded-none`) with rounded inner micro-elements (`rounded-xl` icons, `rounded-full` badges, `rounded-md` controls).
- **Dependencies**: Includes `html2pdf.js` (`npm --prefix crm-web i html2pdf.js`) for client-side PDF export rendering.

## 100% Task 4 Specification Matrix & Gap Resolutions

### 1. BDE vs. ISE Role Scoping Distinction
- **Super Admin (Rank $\ge$ 100)**: Global cross-company & branch visibility.
- **Company Admin (Rank 80–99)**: Company-wide revenue data.
- **Branch Manager (Rank 60–79)**: Branch-scoped revenue data.
- **BDE (Rank = 40)**: **Personal Scoped Revenue** (`closedById = actor.id`). BDE only sees revenue generated by their own closed deals.
- **ISE (Rank = 20)**: **Branch Scoped Read Access** (`branchId = actor.branchId`). ISE can view branch-wide revenue metrics to support sales operations.

### 2. Safe `RevenueLog` & `Deal` Join Query
- Queries `RevenueLog` for canonical revenue figures (`revenueAmount`, `revenueDate`) joined with `Deal` (`closedById`, `opportunity.teamId`) so team & employee attribution works without requiring unexecuted DB schema migrations.

### 3. Multi-Format Export Support (`html2pdf.js` Integration)
- Installs `html2pdf.js` (`npm --prefix crm-web i html2pdf.js`).
- Upgrades `useExport.js` to support **Excel (.xlsx)**, **CSV (.csv)**, and **PDF (.pdf)** formats.

### 4. Branch Revenue Frontend Table
- Added `[NEW] BranchRevenueTable.jsx` to render `/api/reports/revenue/branch` cross-branch comparisons when logged in as Super Admin or Company Admin.

### 5. Server-Side Export & Audit Logging
- Export logging endpoint `POST /api/reports/revenue/export-log` (protected by `hasPermission("REPORT", "canCreate")`) creates an `ExportLog` record AND generates an `AuditLog` entry using the audit pattern in `user.repository.js` to record write actions in the database.

### 6. Correct API Route Mounting Entry Point
- Routes mounted in **`crm-api/src/index.js`** at line 120 (`app.use("/api/reports/revenue", revenueReportRoutes)`).

### 7. Division-by-Zero Safety Guards
- All growth formulas implement zero-division safety:
  ```javascript
  function calculateGrowth(current, previous) {
    const curr = Number(current) || 0;
    const prev = Number(previous) || 0;
    if (prev <= 0) return curr > 0 ? 100 : 0;
    return Number((((curr - prev) / prev) * 100).toFixed(2));
  }
  ```

## REST API Endpoint Specification

| Method | Endpoint | RBAC Permission | Description | Query / Body Parameters |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/reports/revenue/summary` | `REPORT:canView` | Financial KPIs (Total, Monthly, Quarterly, Yearly, ADS, Growth %) | `rankingPeriod`, `companyId`, `branchId`, `teamId` |
| `GET` | `/api/reports/revenue/monthly` | `REPORT:canView` | Month-by-month financial statement & MoM Growth % | `page`, `limit`, `year`, `companyId`, `branchId` |
| `GET` | `/api/reports/revenue/quarterly` | `REPORT:canView` | Quarter-by-quarter financial breakdown & QoQ Growth % | `page`, `limit`, `year`, `companyId`, `branchId` |
| `GET` | `/api/reports/revenue/product` | `REPORT:canView` | Revenue by Product/Course (ASP, Sales Count, Total Revenue) | `page`, `limit`, `rankingPeriod`, `companyId`, `branchId` |
| `GET` | `/api/reports/revenue/team` | `REPORT:canView` | Team revenue attribution & customer additions | `page`, `limit`, `rankingPeriod`, `companyId`, `branchId` |
| `GET` | `/api/reports/revenue/branch` | `REPORT:canView` | Cross-branch financial comparison | `page`, `limit`, `rankingPeriod`, `companyId` |
| `GET` | `/api/reports/revenue/trend` | `REPORT:canView` | Monthly, Quarterly, and YoY trend visualization data | `rankingPeriod`, `year`, `companyId`, `branchId` |
| `POST` | `/api/reports/revenue/export-log` | `REPORT:canCreate` | Log export action in `ExportLog` & `AuditLog` | Body: `{ reportName, exportType, fileName, filtersUsed }` |
